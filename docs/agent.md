# Investigation Agent

## Purpose
The Investigation Agent acts as the final reasoning layer of the pipeline. It takes deterministic, high-recall candidates generated by SQL queries and applies high-precision evaluation using screenplay evidence.

## Tools (ClickHouse MCP)
The agent operates via a strictly defined MCP exposing the following queries:
- `get_entity_timeline(entity_id, from_scene, to_scene)`: Returns all known states/events for an entity.
- `get_scene_text(scene_id)`: Fetches the raw text of a scene.
- `get_state_at_scene(entity_id, scene_id)`: Replays events up to a scene to calculate expected state.
- `find_attribute_changes(entity_id, attribute)`: Filters events by a specific attribute type.
- `get_characters_in_scene(scene_id)`: Contextual query to check who was present.

## Decision Flow
1. **Receive Candidate**: Reads the `CandidateConflict` details (prior state, observed state).
2. **Query Context**: Uses tools to fetch entity timeline and raw scene text around the conflict points.
3. **Analyze**: Looks for bridging events or explicit explanations in the text.
4. **Determine Verdict**: If a bridge is found, `resolved`. If text clearly contradicts, `verified`. If insufficient info, `uncertain`.

## Investigation Limits
- Hard limit of 6 tool calls per investigation to prevent runaway token usage.
- If limits are hit without a conclusion, defaults to `uncertain`.
