# Investigation Agent

## Purpose
The Investigation Agent acts as the final reasoning layer of the pipeline. It takes deterministic, high-recall candidates generated by SQL queries and applies high-precision evaluation using NarrativeUnit evidence (scene, chapter, or passage text, depending on the document type).

## Tools (ClickHouse MCP)
The agent operates via a strictly defined MCP exposing the following queries. These names and signatures are canonical and must match `AGENTS.md`, `backend/agent/tools.py`, and the API schema:
- `get_entity_timeline(entity_id, from_sequence, to_sequence)`: Returns all known states/events for an entity within a temporal sequence range.
- `get_unit_text(unit_id)`: Fetches the raw text of a specific NarrativeUnit.
- `get_state_at_unit(entity_id, sequence_number)`: Replays events up to a sequence point to calculate expected state.
- `find_attribute_changes(entity_id, attribute)`: Filters events by a specific attribute type.

## Decision Flow
1. **Receive Candidate**: Reads the `CandidateConflict` details (prior state, observed state).
2. **Query Context**: Uses tools to fetch entity timeline and raw unit text around the conflict points.
3. **Analyze**: Looks for bridging events or explicit explanations in the text.
4. **Determine Verdict**: If a bridge is found, `resolved`. If text clearly contradicts, `verified`. If insufficient info, `uncertain`.

## Investigation Limits
- Hard limit of 6 tool calls per investigation to prevent runaway token usage.
- If limits are hit without a conclusion, defaults to `uncertain`.
